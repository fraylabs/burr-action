# v1.0.3

The summary and optional bot comment use Burr's `checked_pair_count` and
`pair_set_complete`. A complete report states the interfering and touching
counts and that all other pairs were proven clear. An incomplete report names
unresolved pairs and import/check reasons, and still fails by default. There is
no per-pair clear schema.

`scripts/hosted.mjs` is the importable optional client. The API contract agreed
with the backend is bearer-authenticated licence validation, read-only baseline
retrieval and a history POST with the workflow run ID. One total five-second
deadline covers all requests and response bodies. No token, invalid/malformed
responses, wrong organisations, HTTP errors and network failures skip extras;
the client has no authority to change the geometry verdict. The production
endpoint's paid routes remain disabled pending the backend launch.

On Boat, the actual checker and Action script were run against the demo's
interfering and clear STEP files and Jubilee's camera calibration assembly.
For each model, missing token, invalid token, refused connection, HTTP error
and a real five-second timeout retained the expected exit code: 1, 0 and 1
respectively. The incomplete summary included unresolved pairs and never
claimed its remainder clear. Timeout runs took 5.06, 5.06 and 5.48 seconds,
including geometry and Node startup. These timings exclude installation.

The transport adapter used only for this acceptance run redirects hosted
requests to a disposable local HTTP server; it does not replace the checker.
`node scripts/prove-hosted.mjs` separately exercises the client contract,
malformed responses, a shared deadline across multiple stages and a transport
that ignores aborts. Fixtures do not prove live payment or production service
availability.
